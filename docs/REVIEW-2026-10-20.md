## Befunde und was daraus wurde

### Behoben (P1 — falsches Verhalten)

| Befund | Fix |
|---|---|
| **Matcher: „Reis" → „Milchreis", „Milch" → „Buttermilch"** — die Kopfwort-Regel traf jedes Kompositum | `AMBIGUOUS_COMPOUNDS` (Milchreis, Buttermilch, Erdnussbutter, Sahnesoße …) schließt bekannte Falsch-Komposita aus |
| **Blockliste per Substring** blockte „Weintrauben" (`wein`) und „Eisbergsalat" (`eis`/`salat`) | Blocklisten prüfen jetzt **Tokens** (exakt) statt Substrings; Sorten zusätzlich als Präfix („Gewürzquark") |
| **Rezeptkosten nahmen den besten Namensscore, nicht den günstigsten Preis** | `recipeCost` holt 3 Treffer und nimmt den billigsten — Quarkkeulchen: 8,79 € → **5,83 €** |
| **`matchedCount` zählte nicht preisfähige Zutaten mit** (Salz/Prise) | zählt nur noch preisfähige Treffer; „6 von 8" passt jetzt zur Summe |
| **`helles` klassifizierte „Helles Brot" als Getränk**, `snacks` fraß Hunde-Snacks | `helles bier` statt `helles`, `snacks` entfernt, `hunde`/`hundesnack` → Non-Food |
| **Drogerie-Keywords `creme`/`gel`** hätten Crème fraîche und Gelatine geschluckt | entfernt (spezifische Begriffe wie `handcreme`, `gesichtscreme` bleiben) |
| **Region-Wechsel während eines laufenden Scrapes** hätte Angebote der alten PLZ persistiert | `PUT /region` antwortet **409**, solange ein Scrape läuft; UI erklärt es |
| **`GET /offers/match`** meldete unbekannte Listen als „leer" und warf bei `abc` einen 500er | 400 bei ungültiger ID, **404** bei unbekannter Liste |
| **Favoriten-IDs ungeprüft**, PATCH auf fehlende ID meldete trotzdem Erfolg | `parseId()` → 400, `changes === 0` → 404 |
| **Zweite DB-Verbindung ohne WAL** (`favorites.cjs`) | `journal_mode = WAL` + `busy_timeout = 5000` |
| **Markenvergleich per beidseitigem `includes`** — kurze Marken trafen alles | exakte/Tokengleichheit; Zeilen ohne Marke werden bei gesetzter Marke übersprungen |
| **`days`-Cap 1095 vs. Retention 730** | Cap auf 730 angeglichen |
| **`favKey` case-sensitiv, Server aber `COLLATE NOCASE`** — Herz konnte „nicht gemerkt" zeigen | Client normalisiert jetzt ebenfalls auf lowercase |
| **Filter-Badge zählte `onlyFood` invertiert** | zählt nur, was auch als Tag sichtbar ist |
| **`price-summary`-Antworten konnten sich überholen** | `AbortController` bricht die alte Anfrage ab |
| **`visibleCount` blieb nach Re-Scrape stehen**, Endlos-Scroll begann mitten in der Liste | Reset auf `PAGE_SIZE` beim Laden |
| **Effekt-Abhängigkeiten** (`[id, recipe?.id]`, `openItemsKey` mit `id`) | auf `[id]` bzw. Inhalt ohne `id` reduziert |

### Nicht bestätigt (Fehlalarm der Reviews)

- **„Backdrop-Klick schließt das Filter-Sheet nicht"** — der Handler existierte
  bereits (`onClick` auf `<dialog>` mit `e.target === dialogRef.current`).
- **„`matchItemToOffers` ist evtl. verwaist"** — war zum Review-Zeitpunkt schon
  entfernt; der Linter hat den Rest (`fuzzyMatch`-Referenz) danach gefunden.
- **„Crème fraîche landet in Drogerie"** — die Regel `creme fraiche` in
  `milch-eier` greift vorher; getestet.

### Offen (bewusst)

1. **Keine Authentifizierung** für schreibende/löschende Endpunkte. Für eine
   Ein-Personen-App im LAN/Tailnet vertretbar — aber `DELETE /offers/clear` ist
   damit für jedes Gerät im Netz erreichbar. Kandidat für einen Token-Header.
2. **Store-Label-Maps doppelt** (Client `STORE_LABELS`/`STORE_COLORS`, Server
   `storeDisplayName`) — driftet weiter.
3. **`offersScraper.cjs` 866 Zeilen** mit sechs Zuständigkeiten.
4. **`err.message` in Fehlerantworten** (mehrere Routen) leakt interne Details.
5. **`setRegionPlz` schreibt ohne Lock** (read-modify-write auf die Config).
6. **46 ESLint-Warnungen im Client, 49 im Server** — überwiegend ungenutzte
   Variablen aus älteren Seiten; keine Fehler mehr.
